# PostgreSQL и EF Core

Доступ к существующим таблицам `bikes`, `auth_accounts`, `auth_email_challenges` и `auth_sessions` выполняется через `BikeHubDbContext` в DAL. Dapper и DbUp удалены. HTTP-сервисы контента пока используют моки; аккаунты, коды и сессии хранятся в PostgreSQL.

Свойство аккаунта `PhoneNumber` сопоставлено с прежней колонкой `phone_e164`. Переименование свойства не требует изменения существующей базы.

Приложение использует `IDbContextFactory<BikeHubDbContext>`: каждая операция получает отдельный контекст. Фоновая очистка и параллельные запросы не разделяют `DbContext`. Выдача кодов выполняется под общей транзакционной advisory-блокировкой, подтверждение — под `FOR UPDATE`. Создание аккаунта защищено дополнительной блокировкой по адресу. Обычные чтение, создание, обновление и удаление выполняются средствами EF.

## Миграции

`AdoptExistingSchema` переносит три прежних SQL-миграции в EF через `migrationBuilder.Sql(...)`. Таблицы и индексы создаются с `IF NOT EXISTS`, функция `public.uuidv7()` создаётся только при отсутствии. Изменения её default для `bikes` соответствуют прежней миграции.

Миграция работает на пустой базе, полной прежней схеме DbUp и частичной схеме с существующей таблицей `bikes`. EF создаёт свой журнал `__EFMigrationsHistory`. Прежний `schemaversions` остаётся на месте; переносить или удалять его записи не требуется. Аккаунты, телефоны, коды, сессии и велосипеды не пересоздаются.

`IF NOT EXISTS` не исправляет несовместимую структуру уже существующей таблицы. Для последующих изменений структуры нужны отдельные миграции. Автоматический `Down` начальной миграции запрещён: она принимает существующие таблицы под управление EF и не должна удалять их при откате.

Штатное развёртывание Ansible по-прежнему сначала запускает Job с `--migrate-only`, затем обновляет API. Строка подключения передаётся существующим Secret как `ConnectionStrings__BikeHub`; новые секреты не требуются. Миграции внутри Job применяются через `Database.MigrateAsync`. Ключи cookie и OTP не связаны с EF и при этом переходе не меняются.

## Инструменты разработчика

Из корня репозитория:

```bash
dotnet tool restore
dotnet ef migrations list --project src/BikeHub.Dal --no-connect
dotnet ef migrations has-pending-model-changes --project src/BikeHub.Dal
dotnet ef migrations add ChangeName --project src/BikeHub.Dal
```

Локальная версия `dotnet-ef` закреплена в `dotnet-tools.json`. Design-time фабрика использует `ConnectionStrings__BikeHub` из окружения; без неё задано локальное подключение `localhost/bikehub` без пароля. Генерация миграций не требует доступа к серверу. Для применения миграций CLI использует ту же переменную окружения; не передавайте пароль аргументом команды и не сохраняйте его в репозитории.

```bash
dotnet run --project src/BikeHub.Api --no-launch-profile -- --migrate-only
```

Тесты с одноразовым локальным PostgreSQL (Testcontainers сам запускает контейнер, нужен Docker):

```bash
dotnet test BikeHub.sln --disable-build-servers
```

Проверяются новая и существующая схемы, повторное выполнение raw SQL, сохранение данных и старого журнала, совпадение snapshot с моделью, EF-обработчики велосипедов, одноразовость кодов и конкурентные лимиты. Оригинальные SQL-скрипты DbUp сохранены только как тестовые fixtures.
