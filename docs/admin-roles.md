# Роли аккаунтов

Роль хранится в `auth_accounts.role` отдельно в каждой схеме: `public` для основного
контура и `staging` для тестового. Значения `AccountRole`: `Member`, `Moderator`, `Admin`.
Новый аккаунт получает `Member`. Список `Moderation:ModeratorEmails` продолжает
давать существующим модераторам их прежние права.

`Admin` включает модерацию и открывает `#/admin`: общие счётчики аккаунтов и жалоб,
ссылки на модерацию публичных материалов и жалоб на сообщения. Свободного доступа
к личной переписке роль не даёт. Модератор не может блокировать администратора.
Текущая роль видна в настройках аккаунта.

В правом нижнем углу карточки чужой записи в ленте, бортжурнале и результатах поиска,
а также внизу открытой записи администратору доступна иконка щита **«Меню модерации»**.
Она открывает меню с пунктом **«Удалить запись пользователя»**, жалобой и переходом
к жалобам на материалы. Для автора меню с иконкой многоточия содержит редактирование
и удаление своей записи. Меню поддерживает клавиатуру, Escape и закрытие снаружи;
форма редактирования или жалобы закрывается отдельно, своими кнопками.
После удаления из карточки текущая страница остаётся открытой. Подтверждение показывает
название записи и её автора. Запись исчезает
из ленты, поиска и бортжурнала, её комментарии становятся недоступны. Велосипед,
аккаунт автора и другие записи сохраняются. Используется существующее мягкое
удаление (`is_deleted`), ссылки на фотографии этой записи очищаются. Кнопка
«Восстановить» в модерации не возвращает удалённые записи — для временного скрытия
используйте «Скрыть» в жалобе.

`DELETE /api/posts/{id}` разрешён автору либо администратору с актуальной ролью
в подтверждённой сессии и требует CSRF-токен. Модератор может скрыть запись,
но удалять чужие записи не может. Право редактирования остаётся только у автора.

## Первое назначение

После выкладки и применения миграции оператор может назначить администратора
существующему аккаунту с подтверждённой почтой:

```bash
ssh -i ~/.ssh/truenas_admin ansible@192.168.0.49 \
  'sudo -n k3s kubectl -n bikehub exec deployment/bikehub-api --container=api -- dotnet BikeHub.Api.dll --grant-admin admin@example.org'
```

Для staging используйте `deployment/bikehub-staging-api`. Команда не создаёт
аккаунт, не подтверждает почту и не разблокирует пользователя. Она возвращает
идентификатор аккаунта, роль и признак изменения; повторное назначение безопасно.
Команда запускает только операцию с базой и завершает процесс, без HTTP-сервера
и фоновой отправки писем. Она не доступна через HTTP.

Назначение сохраняется при перезапуске и следующей выкладке. Сессии проверяют роль
по базе при каждом запросе, поэтому для появления меню достаточно обновить страницу.
Отозванная в базе роль перестаёт давать доступ и со старой cookie.

`GET /api/admin/overview` защищён отдельной серверной политикой: требуется
подтверждённая сессия с актуальной ролью `Admin`. Роль нельзя передать при регистрации
или изменении профиля. Миграция добавляет колонку и ограничение через повторяемый
raw SQL с `IF NOT EXISTS`, сохраняя существующие назначения.
