# Ники и идентификаторы

У аккаунта остаётся внутренний UUID — ключ PostgreSQL и связей материалов. Публичная идентичность — уникальный `@ник`, выбираемый при регистрации. Допустимы 3–32 латинские буквы, цифры и подчёркивание; регистр не учитывается, значение сохраняется в нижнем регистре. Технические UUID и служебные имена не допускаются. Имя для отображения остаётся отдельным редактируемым полем; если при регистрации его не указать, используется ник.

Выбранный ник нельзя изменить или очистить через профиль. Старые аккаунты без ника выбирают его один раз после входа. Пользователь может выйти из этого окна и просматривать сайт анонимно. Миграция сохраняет пользовательские ники, но очищает `handle`, совпадающий с UUID самого аккаунта. UUID больше не подставляется в публичное поле ника. Ранее выданные коды регистрации без ника ещё могут завершиться — такой аккаунт пройдёт тот же одноразовый выбор.

Ник хранится в заявке подтверждения почты. Проверка доступности до отправки кода не резервирует его: окончательное назначение выполняется только после правильного кода. Конкурентные подтверждения сериализуются блокировкой, а регистронезависимый уникальный индекс PostgreSQL дополнительно защищает от дубликатов. Если между выдачей и подтверждением кода ник занят, возвращается 409, аккаунт и сессия не создаются. Нужно выбрать другой ник и запросить новый код с учётом ограничения частоты.

Публичные ссылки используют `#/u/nickname`. Старые ссылки `#/user/{uuid}` продолжают работать. Backend:

- `GET /api/users/by-nickname/{nickname}` — публичный профиль по нику.
- `GET /api/users/nicknames?q=prefix` — до 10 публичных профилей по префиксу, в том числе с начальным `@`; заблокированные аккаунты и аккаунты без ника исключены. Email и телефон не возвращаются.
- `POST /api/users/me/nickname` — однократный выбор для подтверждённого аккаунта без ника; требуется сессия и CSRF. Повтор с тем же ником безопасен, изменение запрещено.

Это задел для подсказок упоминаний. Разбор текста, уведомления и сами чаты здесь не реализованы. При дальнейшем добавлении упоминаний нужно сохранять UUID адресата вместе с текстом, а не находить адресата заново при каждом показе `@ника`. После удаления аккаунта ник может быть выбран новым аккаунтом с другим UUID; старые упоминания не должны перенаправляться на него.
