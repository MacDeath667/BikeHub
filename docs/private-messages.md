# Личные сообщения

API личной переписки реализован; интерфейс пока в работе, интеграционные проверки PostgreSQL ещё выполняются.

Переписка один на один начинается запросом контакта с одним сообщением. Отправитель не может отправить второе сообщение до принятия запроса получателем. Получатель может принять или отклонить; после отклонения отправитель не создаёт новый запрос для той же пары. Получатель может вернуться к отклонённому запросу и принять его. Для пары аккаунтов существует один диалог.

Отправка содержит `clientMessageId`, сохраняемый при повторе запроса. Повтор с тем же ключом и текстом возвращает исходное сообщение; другой текст или диалог с тем же ключом возвращают 409. Порядок сообщений определяется отдельной последовательностью диалога, а не совпадающими датами или случайным порядком UUID. Чтение передаёт номер последнего показанного сообщения и не уменьшает ранее сохранённую позицию.

Лимиты на аккаунт: 60 сообщений за минуту, до 20 ожидающих запросов контакта и 20 новых запросов за сутки, до 500 блокировок и 20 жалоб за сутки. Повтор уже отправленного сообщения работает и при достигнутом лимите. Письма о переписке не отправляются. Уведомление внутри BikeHub создаётся для нового запроса и первого сообщения очередной непрочитанной серии; отдельный счётчик показывает число непрочитанных сообщений. Упоминания внутри личного текста не уведомляют третьих лиц.

Блокировка относится к сообщениям: запрещает отправку в обе стороны и скрывает диалог из обычного списка и счётчиков. История остаётся доступна участнику. Архив личный; новое сообщение открытого диалога возвращает его в обычный список. Удаление сообщения оставляет отметку, текст не возвращается участникам и не восстанавливается повтором отправки.

Жалоба копирует только выбранное полученное сообщение. Модератор видит этот фрагмент и причину, не получает доступ к полной переписке. Снимок жалобы сохраняется при обычном удалении сообщения. Модератор может скрыть сообщённое сообщение и закрыть жалобу; блокировка аккаунта использует существующую модерацию. Содержание сообщений хранится в PostgreSQL; сквозного шифрования и вложений в этой версии нет.

Удаление профиля удаляет написанные им сообщения и связанные жалобы. Собственные сообщения другого участника сохраняются; вместо удалённого собеседника отображается недоступный аккаунт без прежнего ID. При удалении обоих участников пустая переписка удаляется. Блокировки удаляются каскадно. Все адреса API требуют входа, проверяют участие и возвращают `Cache-Control: no-store`.

## API

- `GET /api/messages/peers/{userId}` — адресат и существующий диалог, без создания данных.
- `GET/POST /api/messages/conversations` — список/запрос контакта; список принимает `requests`, `archived` и стандартные параметры страниц (до 50).
- `GET /api/messages/conversations/{id}` — состояние, собеседник и доступные действия.
- `GET .../{id}/messages?beforeSequence=&afterSequence=&pageSize=50` — последняя страница, более ранние или новые сообщения. Оба курсора одновременно запрещены.
- `POST .../{id}/messages` — отправка с `text` и `clientMessageId`.
- `PUT .../{id}/request` с `accept`, `PUT .../{id}/read` с `sequence`, `PUT .../{id}/archive` с `archived`.
- `DELETE .../{id}/messages/{messageId}`, `POST .../{id}/messages/{messageId}/reports` с `reason`.
- `GET /api/messages/blocks`, `PUT/DELETE /api/messages/blocks/{userId}`.
- Модератор: `GET /api/moderation/messages/reports`, `POST .../reports/{id}/resolve`, `PUT .../{messageId}/visibility`. Общий API публичных жалоб личные сообщения не принимает.

Миграция `PrivateMessages` использует повторяемый raw SQL. Блокировки строк аккаунтов выполняются перед блокировкой диалога в общем порядке, включая создание пары, отправку и блокирование контакта; это сериализует конкурентные отправки и операции удаления профиля.
