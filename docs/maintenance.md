# Обслуживание велосипеда

Ссылка «Компоненты и обслуживание» находится в карточке собственного велосипеда. Раздел приватный: заметки, стоимость работ, компоненты и история доступны владельцу. Гость получает 401, другой пользователь — 404. Публичные записи бортжурнала создаются отдельно. Модератор не получает доступ к чужому журналу обслуживания.

Компонент содержит тип, название, модель, дату и пробег установки, личную заметку и необязательный интервал обслуживания в километрах. Архив сохраняет историю и прекращает напоминания. Для велосипеда доступно до 200 компонентов вместе с архивом; списки показываются страницами. Список вариантов для формы работы содержит только ID, название и признак архива и ограничен тем же числом.

Работа содержит тип, описание, дату, пробег, необязательный компонент и стоимость в рублях. Можно отметить начало нового интервала для компонента. При этом следующий порог — максимальный пробег таких работ плюс интервал; без работ используется пробег установки. Отдельный осмотр без этой отметки интервал не сбрасывает. Дата работы должна быть не раньше установки компонента. Редактирование уже существующей работы для архивного компонента разрешено; новые работы с ним не создаются.

Работа с большим пробегом обновляет одометр велосипеда. Добавление старой работы или удаление работы его не уменьшает. Одометр можно отдельно исправить, включая уменьшение с подтверждением в интерфейсе; исторические значения сохраняются. Изменение компонента/работы требует актуальной `revision`, иначе 409.

## Напоминания

Проверка выполняется при изменении пробега (как в этом разделе, так и через существующий редактор велосипеда), добавлении/правке компонента или работы. Данные и событие сохраняются в одной транзакции с блокировкой велосипеда. При достижении порога создаётся одно уведомление внутри BikeHub на пару «компонент + порог пробега». Повторное сохранение пробега не дублирует его. Новая работа, архивирование или изменение интервала исключают неактуальные напоминания из выдачи; новый достигнутый порог создаёт новое событие. Письма не отправляются.

Пробег пока вводится вручную; публикация поста или загрузка GPX его автоматически не меняют. Напоминаний по календарю и автоматического получения одометра из внешних сервисов пока нет. Интервал задаёт владелец, BikeHub не подбирает его за производителя.

## API

Базовый адрес — `/api/bikes/{bikeId}/maintenance`, все действия требуют входа владельца и возвращают `Cache-Control: no-store`.

- `GET /` — велосипед, одометр, число активных и ожидающих обслуживания компонентов.
- `PUT /mileage` с `mileage` — изменение одометра.
- `GET /components?archived=false&page=1&pageSize=20`, `GET /components/options` — компоненты и короткий список для форм.
- `POST /components`, `PUT /components/{id}` — создание/изменение, включая архив.
- `GET /records?componentId=&page=1&pageSize=20` — история, до 50 работ на страницу.
- `POST /records`, `PUT /records/{id}`, `DELETE /records/{id}` — запись, правка, удаление работы.

Даты проверяются по переданному IANA-часовому поясу; без него API использует UTC. Миграция `BikeMaintenance` повторяемая, raw SQL с `IF NOT EXISTS`. Физическое удаление профиля каскадно удаляет журнал его велосипедов. Проверка удаления профиля дополнена данными новых разделов и проверкой сохранения чужих материалов и ответов.
