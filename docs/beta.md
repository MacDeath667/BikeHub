# Подготовка к закрытой бете

Реализовано в `engineering/dumb-implemnent`:

- Аккаунты, велосипеды, записи, комментарии, лайки, закладки, подписки и участие в сообществах хранятся в PostgreSQL через EF Core.
- Редактирование и мягкое удаление своих материалов; проверки владельца выполняются сервером.
- Профиль: имя, уникальный адрес, город, описание, аватар.
- JPEG/PNG/WebP: до 10 МБ / 24 мегапикселей, максимум 1600 px, удаление метаданных, вывод WebP. Неопубликованные фото видит только владелец. Фотографии скрытого или заблокированного контента не публикуются, если не используются другим видимым материалом.
- Лимиты фото: 50 загрузок в сутки и 250 МБ на аккаунт. Изменяющие HTTP-запросы ограничены 60 в минуту на пользователя/IP в каждом процессе API; это не распределённый лимит.
- Жалобы, скрытие материалов, блокировка с отзывом сессий. Модераторы назначаются конфигурацией по подтверждённой почте, а не через клиент.
- Миграция добавляет таблицы/колонки через raw SQL `IF NOT EXISTS`, не удаляет прежние данные. Старые демонстрационные данные из памяти не переносятся.
- Compose сохраняет фотографии в `media-data`; NAS использует PVC `<auth-key-claim>-media`, отдельно для staging и production.

## Настройки

`Media:RootPath` — каталог фотографий. По умолчанию `App_Data/media` в каталоге API; в контейнере `/app/data/media`.

`Moderation:ModeratorEmails` — список email. Для локального Compose можно добавить `Moderation__ModeratorEmails__0` в environment API. В Ansible укажите `bikehub_moderator_emails: ['moderator@example.org']` в собственных переменных. Добавляйте только доверенные подтверждённые аккаунты.

При публикации через Nginx Proxy Manager обновите Custom Location по `infra/nginx-proxy-manager/bikehub.conf`: лимит тела запроса должен пропускать фотографию вместе с multipart-обёрткой. Изменение файла не применяет настройки панели автоматически.

## Ещё до приглашения пользователей

- Настроить и **проверить восстановление** резервной копии PostgreSQL, фотографий и ключей сессий. Том Docker/PVC сам по себе не является резервной копией.
- Проверить staging по публичному пути, отправку реальных писем, назначить модератора и провести ручную приёмку с двух аккаунтов.
- Подготовить политику обработки данных, согласия, контакты поддержки и процедуру удаления аккаунта. Вопросы размещения данных и подтверждения телефона для запуска в РФ остаются открытыми; эта ветка их не решает.
- Добавить очистку неиспользуемых фотографий и инструмент удаления данных пользователя. Сейчас такие файлы учитываются в квоте и сохраняются до ручного обслуживания.
- При нескольких узлах API перейти с локального PVC на общее файловое/объектное хранилище. Реплики на одной VM могут пользоваться текущим томом; распределённые лимиты пока не реализованы.
- Уведомления об ответах и подписках пока отсутствуют.

Рабочий production и Nginx Proxy Manager в рамках этого этапа не обновлялись.

## Проверка этапа

- `dotnet test BikeHub.sln -c Release --disable-build-servers -m:1`: 52 теста API и 37 тестов почты прошли.
- `npm --prefix Web run build`: TypeScript и production-сборка прошли.
- `ansible-playbook infra/tests/staging.yml`: изоляция схем, ресурсов и томов staging проверена без подключения к NAS.
- Локальный Compose: регистрация с письмом в Mailpit, загрузка PNG с перекодированием в WebP, создание велосипеда и записи. После пересоздания API сессия, материалы и фотография сохранились. Тестовая сессия завершена; проверочные материалы оставлены локально с названием «Проверка…».
