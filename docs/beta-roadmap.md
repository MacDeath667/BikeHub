# План доведения BikeHub до закрытой беты

Дата начала: 16 ноября 2026. Рабочая ветка: `engineering/dumb-implemnent`.

Цель — закончить основные повседневные сценарии велосообщества и сделать их проверяемыми. Выполнение последовательное, законченными этапами: код, существенные проверки, документация, коммит и push. Локальный стенд и staging обновляются по готовности этапа. Production обновляется после итоговой проверки совместимости; реальные данные, секреты и настройки Nginx Proxy Manager сохраняются.

## Бюджет и остановка

- На старте использовано 19% недельного лимита аккаунта, осталось 81%.
- Пользователь разрешил потратить дополнительно до 50 процентных пунктов недельного лимита. Верхняя граница общего расхода — 69%.
- При 64% прекращать начинать новые функции и завершать текущий законченный блок, оставляя запас на проверки и отчёт. При 69% не начинать никаких новых изменений.
- Перед существенным этапом и не реже раза в 10 минут проверять фактический расход через `get_usage_limits`. Лимит общий: другие чаты также расходуют этот запас.
- По явной инструкции пользователя от 16 ноября новая длительная цель создана без отдельного токенового потолка; действует только недельный контроль выше.
- Текущее недельное окно заканчивается 18 ноября 2026 в 10:21:01 по Москве. Автоматически переходить на бюджет следующей недели нельзя. Сброс лимита, изменение окна или недоступная телеметрия требуют остановки новых работ и отчёта.
- Сбросы лимитов, покупка кредитов и платные внешние сервисы не входят в задачу.
- Не расходовать лимит ради его расходования. Недоделанное фиксируется здесь без объявления его готовым.

## 1. Надёжность и проверяемость

- [x] CI: backend build/test, frontend test/build, проверки Ansible без рабочих серверов. [Первый успешный прогон](https://github.com/MacDeath667/BikeHub/actions/runs/43868668780): все три job зелёные.
- [x] Локальные Ansible backup/restore-check v2: отдельные БД API и почты, Kafka, media и session keys; копия при остановленных writers и брокере, восстановление в изолированные одноразовые ресурсы, сравнение числа строк, SHA-256 файлов и позиций топика. Версия 1 сохраняла только БД API — исправлено, старые копии проверяются с явным ограничением.
- [ ] Резервная копия API/PostgreSQL, почтовой очереди, media и ключей сессий; доступ к секретам только на сервере.
- [ ] Проверка восстановления в отдельной БД и отдельных каталогах/томах: ни production, ни staging не перезаписываются.
- [ ] Зафиксированы ограничения консистентности, место хранения, права доступа, сроки хранения и порядок восстановления.
- [ ] Пройдена проверка на локальном стенде и, при доступности NAS, на сервере.

Приёмка: восстановлены проверочные записи и фотографии, читаются восстановленные данные и история миграций; оригинальная среда продолжает работать. Автоматическая копия на том же диске не считается защитой от потери диска/VM.

Доступность на 16 ноября: пользователь находится вне домашней сети, SSH к NAS/VM недоступен. Подготовка и локальная проверка продолжаются, серверное восстановление и выкладка на staging ожидают доступа. Локальный OrbStack был выключен и запущен для одноразовых тестовых контейнеров.

Место серверных копий: пользователь выбрал заглушку `bikehub_backup_root: /dev/null` в Ansible-конфиге до возвращения домой и создания dataset. Заглушка должна останавливать серверный сценарий до любых действий с работающими сервисами и секретами.

Исходная проверка: 76 тестов API, 38 тестов почты, 18 frontend-тестов, production build и четыре Ansible-прогона прошли. Локальный Compose собран и запущен. Сквозной recovery-прогон создал одноразовый аккаунт через Mailpit, велосипед, запись и фотографию; после backup/restore сохранились исходная сессия, материал и фото. Проверочный аккаунт удалён отдельным email-кодом. [Команды и границы backup/restore](backups.md).

Проверены 83 теста API, 38 тестов почты, 33 frontend-теста и production-сборка. [Устройство и ограничения черновиков](drafts.md), включая случай ошибки очистки уже опубликованного черновика. Локальный стенд обновлён: два одноразовых аккаунта через Mailpit, приватное фото, перезапуск API с сохранением сессии и черновика, публикация и отклонение запоздалого сохранения прошли; проверочные аккаунты удалены. NAS ожидает доступа из домашней сети. Из-за npm registry timeout web-образ локально собран из проверенного `Web/dist`; штатный Dockerfile остаётся сборкой из исходников.

Приёмка: повторное открытие формы/перезагрузка возвращает содержимое; переключение аккаунта не подставляет чужой черновик; опубликованный черновик не восстанавливается повторно.

Приёмка: поиск не возвращает скрытые/удалённые/заблокированные материалы, имеет стабильную пагинацию, корректно обрабатывает Unicode и специальные символы.

- [ ] Проверены локальная и staging выкладки; подготовлено итоговое резюме и готовность production.

Доводка 16 ноября: чтение одного сообщества больше не загружает весь каталог; авторы ответов обсуждения загружаются пакетом. Страница с 50 ответами выполняет четыре запроса, скрытые/заблокированные ответы исключены. При ошибке вкладки обсуждений исчезает загрузчик и доступен retry. Проверены 87 тестов API и 38 frontend-тестов. Штатная Docker-сборка web из исходников снова проходит после ограничения одновременных соединений npm. Недельный расход — 25%, окно и порог 69% прежние. Для NAS ожидаются доступ к домашней сети и путь внешнего места хранения копий.

Каталог: загрузка по 20 групп с серверным фильтром, боковая панель при старте — пять. Старый массив ограничен 100; сообщество за этим пределом доступно по ID и в пагинации. Поднабор из восьми API-тестов и все 40 frontend-тестов прошли. Docker-контекст проверен отдельной сборкой: существующие `.local` и `.codex-attachments` не копируются; OAuth-файлы и прочее локальное приватное состояние также исключены правилами ignore.

Уведомления: 79 тестов API, 38 тестов почты, 21 frontend-тест и сборка прошли. Серверная выкладка ожидает доступа к NAS. Подробности в [инструкции уведомлений](notifications.md).

Мобильный интерфейс пользователь проверяет сам. Отключённый browser use не обходить. Без реального визуального прогона не объявлять визуальную приёмку выполненной.

## Границы

SMS-провайдер, юридические документы, размещение персональных данных, платежи/монетизация, чат, выделенное объектное хранилище и многосерверный кластер требуют отдельного решения. Они не блокируют независимую работу над указанными этапами, но остаются условиями соответствующего публичного запуска. Не менять публичные обещания о юридическом соответствии без оснований.
